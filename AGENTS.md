# AGENTS.md

Frontend-only React 19 + Vite 8 + TypeScript SPA ("SSM") over Supabase. No tests, no CI, no ESLint; env files are gitignored (`*.local`).

## Commands

- **Dev**: `npm run dev` (or `RUN.bat`). No port pinned in `vite.config.ts`; `cleardata.ps1` assumes `http://localhost:5173`.
- **Verify before claiming done**: `npm run lint` then `npx tsc -b`. Lint baseline is exactly 2 warnings (`react/only-export-components` in `src/components/ui/button.tsx` and `src/components/ui/tabs.tsx`) — leave them.
- **Build**: `npm run build` (`tsc -b && vite build`). There is no test or `typecheck` npm script; don't invent one.
- **Live DB probes**: `.\check.ps1` checks connectivity, tables, anon read, QCM columns, then anon insert (it creates and deletes a throwaway `quizzes` row). It needs `.env.local` with `VITE_SUPABASE_URL` + `VITE_SUPABASE_PUBLISHABLE_KEY` — it ignores `VITE_SUPABASE_ANON_KEY`. `.\probe-qcm.ps1` is the focused QCM variant.
- **Clear local state**: `.\cleardata.ps1` wipes only `localStorage` over CDP (`localhost:5173`, debug port 9222). The session lives in cookies, so it does not log you out.
- **Schema first**: before editing Supabase-querying code, confirm live columns (they drift from `schema.sql`). Run `/verify-fix` (`.opencode/command/verify-fix.md`) or ask the user; never guess.

## Environment & Backend

- `.env.local` at the **root only** (`supabase/.env.local` / `supabase/.env.example` are never loaded) needs `VITE_SUPABASE_URL` plus `VITE_SUPABASE_ANON_KEY` or `VITE_SUPABASE_PUBLISHABLE_KEY`. `src/lib/supabase.ts` throws at import when missing; restart Vite after env edits.
- **No Supabase Auth, no per-user RLS**: every client shares the anon/publishable key and `schema.sql` creates `<table>_anon_all` policies (`using (true) with check (true)`). RLS grants no authorization — never store anything sensitive. Password columns are plaintext and compared client-side; `@supabase/ssr` is installed but unused for auth.
- **`schema.sql` is not auto-applied**: paste `supabase/schema.sql` into the SQL Editor (idempotent). `CREATE TABLE IF NOT EXISTS` will not add columns to existing tables, so column gaps need the patches in `supabase/`: `qcm-migration.sql`, `publications-type-migration.sql`, `exams-type-duration-migration.sql`, `exam-attachment-migration.sql`, `exams-semester-migration.sql`, `planning-class-time-migration.sql`.
- **Single data layer**: all Supabase I/O goes through `src/lib/api.ts` (~4k lines); add tables/columns/mutations there, never inline in components. Rows are `snake_case`, mappers convert to `camelCase`. Wrap every query builder in `withTimeout()` (15s default, 8s probes) or a page can sit on Loading forever; throw `new Error(error.message)` and render via `errorMessage()`. No react-query/SWR — pages fetch in `useEffect` into local state, refreshed by realtime or `useRefetchOnFocus()` (one refetch after ≥5s hidden).
- **Optional schema is probed at runtime — never reference a column that may not exist**; PostgREST rejects unknown columns and the whole query dies. Helpers: `detectPaymentsCapabilities()`, `generalTrashCapabilities()`, `hasCourseMaterialsColumn()`, `hasEventsTable()`, `hasEventAttendeesColumn()`, `hasExamAttachmentColumn()`, `hasExamSemesterColumn()`, `hasPlanningClassTimeColumns()`, `missingQuizColumns()`/`assertQuizzesReady()`. They fail with an actionable "run `<file>.sql`" message; the app degrades to in-memory stand-ins when a flag is absent.
- **Storage buckets are case-sensitive**: `cours-covers`, `cours-PDF`, `cours-videos` (paths via `src/lib/courseBuckets.ts`), `event-covers`, `university-logo`, `exam` (hardcoded in `src/lib/api.ts`). The legacy `cours` bucket still serves older absolute `thumbnail_url`s.
- **Realtime** publication covers only `students, teachers, courses, publications, course_reviews, events, quizzes, quiz_responses` — not attendance or payments. Use `subscribeToTable(table, () => refetch())` on live pages.
- **Session**: cookies via `src/lib/session.ts` (`role`, `currentStudentId`, `currentTeacherId`, 24h `max-age`) — users re-login daily by design, not a bug. `localStorage` holds only the `ssm-settings` cache and announcement read-state (`ssm-read-announcements-<role>`). Guards in `src/App.tsx`; soft-deleted records end the session.

## Architecture

- **Routes (4)**: `/login`, `/dashboard` (operator), `/student`, `/teacher`, role-guarded in `src/App.tsx` with a wildcard bounce. Two files named `DashboardPage.tsx` exist: `src/pages/DashboardPage.tsx` is a thin `/dashboard` wrapper around `<Layout />`; `src/pages/dashboard/DashboardPage.tsx` is the operator stats section.
- **Sections are state, not routes**: each layout swaps sections via a `pages` map driven by an in-app history stack (`src/hooks/viewHistory.ts` + `src/hooks/ViewHistoryProvider.tsx`) — `active` is `currentSection.key`, sidebar clicks call `pushSection(key, label)` (never local `setState`), and `HeaderBackButton` pops the stack. Adding a section means updating **both** the menu and the `pages` record or it silently never renders. Nested full-page views (course details in both portals, the teacher event detail, quiz taking) register with `useNestedView(open, key, label, onClose)` so the header arrow and their own Back button agree.
  - Operator: menu in `src/components/sectionMenu.ts` (typed `MenuKey`), map/render in `src/components/Layout.tsx`. Pay and Events are collapsible parents. `publications` (broadcast composer) and `news-center` (`src/pages/publications/NewsCenterPage.tsx`) both read the `publications` table.
  - Teacher: `src/pages/teacher-portal/TeacherLayout.tsx` builds `pages` **inside** the component (closes over `setOpenEventId`; event detail is a swapped page, not a route). Its one collapsible parent, `"Exams"`, has a key outside the `PageKey` union (`openSections` tracks it). `QcmPage` owns its `editing` state.
  - Student: `src/pages/student-portal/StudentLayout.tsx` (menu + pages, incl. `qcm` → `src/pages/student-portal/StudentQcmPage.tsx`). `MyInfoPage.tsx` exists in that folder but is not in the menu, and student settings are a separate page (`StudentSettingsPage.tsx`), not the operator `src/pages/settings/SettingsPage.tsx`.
- **Student profile dialog** (`src/components/StudentProfileDialog.tsx`): clicking a row (or the name) in the operator Students list and both teacher My Class tables opens it. It is a dialog, not a route; header = initials avatar (`UserAvatar` — there is no photo column), name, program/training tags, and Email/Call/Message/Edit actions. Tabs are `Overview`, `Contact`, `Academic Info`, `Activity`; only Activity hits the API (`loadStudentAttendance(fullName)`, attendance is denormalized by name). All other fields come from `Student`, and teachers get no `onEdit`.
- **Login** (`src/pages/LoginPage.tsx`): `admin`/`admin123` → operator; teachers matched by **exact, case-sensitive** trimmed full name; students case-insensitively. `blocked` is checked only after the password matches; wrong input gets one generic message.
- **Branding**: `src/main.tsx` loads settings once through `src/lib/branding.ts` (`useBranding`, `brandTitle`, `setBrandingFromSettings()`) and applies `dark_mode`; `system_name` falls back to "SSM".
- **Accounts**: `password`/`blocked` columns on people tables (null password = no account), plaintext and compared client-side. Defaults `tch123`/`std123` in `src/pages/users/userAccounts.ts`.

## Data-model Gotchas (must know)

- **Programs/trainings have two sources**: DB tables `programs`/`trainings` drive form dropdowns and `resolveProgramTrainingIds()`; empty tables silently drop the program/training on insert. Static `PROGRAMS`/`TRAININGS`/`COURSES` in `src/lib/trainings.ts` only seed the student schedule. `students` store FKs; `teachers` use free-text `program`/`training`/`specialty`.
- **Class assignment uses specialty aliases**: `teacherCourseAssignment()` tries the profile, then `teachers.specialty` via hand-maintained `SPECIALTY_CLASS_ALIASES` (keys are `normalizeSpecialtyKey()` output, `&`→space), then the teacher's courses. Targets are `"CODE / Name"`; there is no FK, and mismatches show an amber banner on the Class page. `supabase/backfill-teacher-classes.sql` is optional and flags 2 ambiguous rows — don't run it blindly.
- **Soft delete by default**: `is_deleted=true` + `deleted_at`; lists filter `.or("is_deleted.is.false,is_deleted.is.null")`. Trashed people cannot log in and their session ends (`getStudentById`/`getTeacherById` return null). Payments have their own trash; students/teachers/publications/attendance share `GeneralTrashPage` (purge calls `hardDelete*`). App-level cascade only for exams (`deleteExamCascade` → grades); deleting a course hard-deletes it and the FK cascades `course_reviews`.
- **Denormalized names**: `attendance` and `course_reviews` snapshot `student_name`; `events` store `organizers`/`members`/`attendees` as `uuid[]` with no names. Resolve at read time and skip missing ids.
- **Courses**: `listTeacherCourses({ teacherId?, programId?, trainingId? })` — pass `{ teacherId }` in teacher contexts, `{}` only to fetch everything. Add Course has no program/training selectors (inferred via `teacherCourseAssignment()`, refetched at save). `saveTeacherCourse()` throws, `deleteTeacherCourse()` returns a boolean. Thumbnails are downscaled to ≤400px JPEG → `cours-covers`; `published` is an auto `published_at` shown as "Added <date>"; `day`/`time_slot` exist but are not written.
  - `courses.materials` can be a JSON **string** on older rows — always use `toMaterialList()`; likewise `toSkillList()` for `skills`. Wrap student detail sections in `ErrorBoundary`.
  - `courses.level/format/duration` are display strings and `skills` is `text[]` (not jsonb) — don't "normalize" without a migration.
  - Student courses = static `COURSES` (seeded, no id/teacherId) merged with live `courses` for the student's class via `listTeacherCourses({ programId, trainingId })`, else a name fallback. Many trainings have no seeded course.
  - Thumbnails resolve Storage first, then `thumbnailForTraining()` in `src/lib/courseDisplay.ts` (`src/assets/img/courses/<slug>.jpg`, accents/apostrophes → `-`), then a gray placeholder.
- **Events vs Publications (different tables)**: `events` are rich items from the admin Events page; `events.type` is plain `text` with no CHECK, so `EVENT_TYPES` in `src/lib/api.ts` is the only limit. `partners` is jsonb `{name,link}` (older `text[]` read via `toPartnerArray()`). `attendees` (teacher RSVPs) is excluded from `saveEvent()` so the operator form can't overwrite it; `setEventAttendance()` is a read-modify-write on the uuid[]. Covers → `event-covers`. `publications` is broadcast notifications only (`recipients` `text[]`, `type` limited to `urgent|warning|info` by `src/pages/publications/publicationTypes.ts`).
- **Attendance is a denormalized log**: `src/pages/absence/AttendanceLog.tsx` writes `id, type('student'|'teacher'), full_name, class_name, date, time, created_at` plus optional `program`/`training` snapshots — there is **no** `student_id`/`teacher_id`/`present`. `attendanceToWriteRows()` always resolves program/training (explicit wins, else lowercase-name backfill) and falls back `class_name` → training → program → specialty → `"General"`. One table, no Save button, client-side filtering; students read via `loadStudentAttendance()`.
- **Exams/Grades**: exams are scoped to `teacher_id`; new rows store `type` + `duration` + `semester` (`'Semester 1' | 'Semester 2'`, plain text, limited only by `EXAM_SEMESTER_OPTIONS` in `src/pages/teacher-portal/exams.ts`; probe before writing). `program`/`training` are legacy snapshots and the `course` column is unused. Attachments keep the display name in `file_name` and the public `exam` bucket URL in `attachment_url`. The Exams sidebar parent swaps separate sections, not tabs: `CreateExamView`, `ExamsTableView` (filters, inline edit, viewer/download, cascade delete) and `ExamScoreView` (grade matrix), sharing `useTeacherExams()` + `src/pages/teacher-portal/ExamForm.tsx`. Delete confirms via `countGradesForExam` then `deleteExamCascade`; `saveGradesForExam` replaces every grade for the exam (blank clears). Rosters come from `classRosterForTeacher()`.
- **QCM**: `quizzes` (`teacher_id`, nullable `course_id`, `questions` jsonb `{id,text,options[4],correctIndex}[]` — **index**, not letter) read via `toQuizQuestions()` (jsonb may arrive as a string). `quiz_responses` is unique on `(quiz_id,student_id)`, stores `{questionId:index}` + `score`. Published quizzes lock editing (unpublish to edit). Reviews resolve names via `classRosterForTeacher()` ("Removed student" when absent). Student side: `listPublishedQuizzes(courseIds)`, `listStudentQuizResponses()`, `submitQuizResponse()` (upsert), `scoreQuizAnswers()`; an empty `course_id` means visible to every student. Every call runs `assertQuizzesReady()` first, so partial live schemas fail with the migration message.
- **Announcement unread badge**: `useUnreadAnnouncements(role)` counts `publications` whose `recipients` include the role, minus ids in `src/lib/announcementReads.ts` (localStorage `ssm-read-announcements-<role>`). `role` is the plural `RecipientType` (`"teachers" | "students"`), not `"teacher"`/`"student"`. Only teacher/student sidebars show it; their announcement pages mark the list read on mount and fire a custom event so the badge updates immediately.
- **Payments audit**: `updatePayment()` diffs fields and **appends** one `edit_history` jsonb entry (`changedAt, changedBy, changes:[{field,from,to}]`), with `changed_by` taken from the cookie role (`"operator"`). Soft delete/restore only flips flags. Receipts (`src/pages/pay/PaymentReceiptModal.tsx`) print only `#receipt-print-area` via the `receipt-printing` body class (hide chrome with `.receipt-no-print`).
- **Settings**: key/value `settings` table via `getSettings`/`saveSettings` (SQL null clears). Keys: `system_name`, `university_name`, `logo_url`, `language`, `dark_mode`, `license_activated_at`, `license_token`. Falls back to the `ssm-settings` localStorage cache and mirrors writes into it. Language is stored only. The System tab's "Sync Data" runs `reconcileAttendanceProfiles()` (backfills NULL/generic program/training by case-insensitive name, never overwrites) — mirrors SQL `public.reconcile_attendance_profiles()`.
- **License**: no backend. Expiry = `license_activated_at` + `LICENSE_TERM_MONTHS` (`src/lib/license.ts`); accepted tokens live in `LICENSE_TOKENS` and root `token.md` is their human mirror — **keep them in sync** (the app cannot read markdown). All are `fake-token-…` placeholders.
- **Planning**: `src/pages/teacher-portal/PlanningPage.tsx` filters by `teacherId` and hand-rolls a Mon–Sun week (no date lib; anchor `startOfWeek(today)`, step ±7). Entries store `course`, optional `class_name`/`session_time` (text window, e.g. `"08:30 - 10:00"`) and the topic (`topic` column, `content` in the app). Excel (SheetJS) / PDF (jspdf-autotable) export only the viewed week and disable when empty.
- **Bulk import**: `.xlsx`/`.csv` parsed client-side with SheetJS (`src/pages/students/importStudents.ts`, `src/pages/teachers/importTeachers.ts`, `src/pages/absence/importAttendance.ts`) then bulk-inserted through `src/lib/api.ts`.

## Stack Quirks

- **Tailwind v4** via `@tailwindcss/vite` — there is **no** `tailwind.config.js`; theme tokens live in `@theme inline` in `src/index.css`.
- **shadcn/ui on Base UI**: `"style": "base-nova"` in `components.json` wraps `@base-ui/react`, not Radix. Add components with `npx shadcn add <component>`; icons are lucide-react.
- **Path alias**: `@/*` → `src/*` is duplicated in `vite.config.ts`, `tsconfig.app.json` and `tsconfig.json` — keep all three in sync.
- **TypeScript**: `verbatimModuleSyntax` (use `import type`), `erasableSyntaxOnly` (no enums/namespaces/parameter properties), `noUnusedLocals`/`noUnusedParameters`. `strict` is **not** enabled; don't turn it on casually.
