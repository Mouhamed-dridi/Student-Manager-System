# AGENTS.md

Frontend-only React 19 + Vite 8 + TypeScript SPA ("SSM"), backed by Supabase. No tests, no CI, no ESLint. Env files are gitignored (`*.local`).

## Setup & Commands

- **Dev**: `npm run dev` (or `RUN.bat`). No port pinned in `vite.config.ts`; `cleardata.ps1` assumes `http://localhost:5173`.
- **Lint**: `npm run lint` (oxlint, `.oxlintrc.json`). Baseline: 2 warnings (`react/only-export-components` in `src/components/ui/button.tsx`, `tabs.tsx`) — do not fix them.
- **Typecheck**: `npx tsc -b`. **Build**: `tsc -b && vite build`. No test or `typecheck` npm script; do not invent them.
- **Verify changes**: run `npm run lint` then `npx tsc -b` (in that order).
- **Live Supabase checks**: `.\check.ps1` (connectivity, table existence/anon read, row counts, QCM columns). Requires `.env.local` with `VITE_SUPABASE_URL` + `VITE_SUPABASE_PUBLISHABLE_KEY` (does **not** accept `VITE_SUPABASE_ANON_KEY` here). Optional `SUPABASE_SECRET_KEY` enables a secret-key check.
- **QCM probe**: `.\probe-qcm.ps1` (focused column + insert probes).
- **Clear local state**: `.\cleardata.ps1` only clears `localStorage` via CDP; session is in cookies (does not log you out).
- **Schema verification**: Before changing Supabase-querying code, confirm live columns (schema drifts). Run the `/verify-fix` command (`.opencode/command/verify-fix.md`) or ask the user — never guess.

## Environment & Backend

- **Supabase required**: `.env.local` needs `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` **or** `VITE_SUPABASE_PUBLISHABLE_KEY`; the PowerShell scripts only read the publishable name. `src/lib/supabase.ts` throws at import if missing; restart Vite after env changes. Only the **root** `.env.local` is read (Vite + both PowerShell scripts resolve from the repo root); `supabase/.env.local` / `supabase/.env.example` are not loaded. `.env.example` documents both key formats.
- **No auth, no per-user RLS**: there are no Supabase Auth accounts — every client uses the same anon/publishable key and `schema.sql` creates `<table>_anon_all` policies (`using (true) with check (true)`). RLS isolates nothing, so never rely on it for authorization; keep that in mind before storing anything sensitive. `@supabase/ssr` is a dependency but unused for auth; the app logs in by comparing a name/password column client-side.
- **Schema is not auto-applied**: `supabase/schema.sql` is the executable source of truth (idempotent). Paste into Supabase SQL Editor to create/update; `CREATE TABLE IF NOT EXISTS` will **not** add missing columns to existing tables. Column-gap patches (all idempotent): `supabase/qcm-migration.sql`, `supabase/publications-type-migration.sql`, `supabase/exams-type-duration-migration.sql`, `supabase/exam-attachment-migration.sql`, `supabase/exams-semester-migration.sql`.
- **Single data layer**: ALL Supabase I/O goes through `src/lib/api.ts` (~3.8k lines). Rows are `snake_case`; mappers convert to `camelCase`. Add new tables/columns/mutations there — never inline in components. Wrap every query builder in `withTimeout()` (15s default, 8s probes): an un-timed call can hang a page on Loading forever. Throw `new Error(error.message)` and render via `errorMessage()`. There is no react-query/SWR — pages fetch in `useEffect` and keep local state; realtime/`useRefetchOnFocus` trigger refetches.
- **Capability probing (critical)**: optional schema detected once at runtime; never reference a column that may not exist (PostgREST rejects unknown columns). App degrades gracefully (in-memory trash stand-ins when the DB flags are absent). Helpers: `detectPaymentsCapabilities()` (payments `is_deleted/deleted_at/edit_history`), `generalTrashCapabilities()` (soft-delete flags on students/teachers/publications/attendance), `hasCourseMaterialsColumn()`, `hasEventsTable()`, `hasEventAttendeesColumn()`, `hasExamAttachmentColumn()` (exams.attachment_url; uploads fail with a "run exam-attachment-migration.sql" message without it), `hasExamSemesterColumn()` (exams.semester; saves fail with a "run exams-semester-migration.sql" message without it), `missingQuizColumns()`/`assertQuizzesReady()` (QCM fails with an actionable "run qcm-migration.sql" message). `check.ps1` probes those QCM columns because live quizzes/quiz_responses often lack `course_id`, `is_deleted/deleted_at`, `updated_at`, `student_id` + anon RLS policies.
- **Storage buckets (case-sensitive)**: per media type via `src/lib/courseBuckets.ts` (single source of truth for course upload/display paths): `cours-covers`, `cours-PDF`, `cours-videos`; plus `event-covers`, `university-logo`, and `exam` (exam PDFs, bucket name hardcoded in `api.ts`). Legacy `cours` bucket holds older absolute `thumbnail_url`s (kept). Buckets + anon policies are in `schema.sql`'s Storage block and the exam migration.
- **Realtime**: `subscribeToTable(table, () => refetch())` on live pages; `useRefetchOnFocus(refetch)` does one refetch on tab regain (≥5s hidden). Realtime publication (from schema bottom) includes: `students, teachers, courses, publications, course_reviews, events, quizzes, quiz_responses` — **not** attendance or payments.
- **Session**: cookies via `src/lib/session.ts` (`role`, `currentStudentId`, `currentTeacherId`; 24h `max-age`, so users re-login daily — expected, not a bug). `localStorage` holds only the `ssm-settings` fallback cache and announcement read-state (`ssm-read-announcements-<role>`). Guards in `src/App.tsx`; deleted records end session.

## Architecture

- **Routes (4)**: `/login`, `/dashboard` (operator), `/student`, `/teacher`. Role guards; wildcard bounces by role. Two files share the name `DashboardPage.tsx`: `src/pages/DashboardPage.tsx` is a thin `/dashboard` wrapper around `<Layout />`, while `src/pages/dashboard/DashboardPage.tsx` is the operator stats section (`getDashboardStats()`).
- **Sections = state, not routes**: each layout swaps sections via `useState` + `pages` map. When adding a section, update **both** the menu list and the `pages` record.
  - **Operator**: menu in `src/components/sectionMenu.ts` (typed `MenuKey`), `pages` map/render in `src/components/Layout.tsx`. Pay and Events are collapsible parents (parent highlights via first child key). `publications` (create broadcast) and `news-center` (`publications/NewsCenterPage.tsx`, edit/soft-delete) both read the same `publications` table.
  - **Teacher**: `teacher-portal/TeacherLayout.tsx` builds its `pages` map **inside the component** (closes over `setOpenEventId`) — event detail swaps in as full page (not route). `QcmPage` owns its own `editing` state. Sidebar has one collapsible parent, `"Exams"` (children `exams-notes`, `qcm`); the parent key is separate from page keys, so the page union `PageKey` excludes it and `openSections` holds toggle state.
  - **Student**: `student-portal/StudentLayout.tsx` (menu + pages), including a `qcm` section (`StudentQcmPage.tsx`) for taking published quizzes. `MyInfoPage.tsx` exists but not in menu. Settings differ: operator `settings/SettingsPage.tsx` vs student `student-portal/StudentSettingsPage.tsx`.
- **Login**: single form (`src/pages/LoginPage.tsx`) checks (1) `admin`/`admin123` → operator, (2) teachers by **exact case-sensitive** trimmed full name, (3) students by **case-insensitive** trimmed match. `blocked` checked only after credentials match; wrong password → generic message.
- **Branding**: bootstrap in `main.tsx` fetches settings once via `src/lib/branding.ts` (`useBranding`, `brandTitle`, `setBrandingFromSettings()`), cached for layouts/Login. `system_name` falls back to "SSM".
- **Accounts**: `password`/`blocked` columns on people tables (null password = no account). Passwords are stored **plaintext** (no hashing) and compared client-side. Defaults: `tch123`/`std123` in `src/pages/users/userAccounts.ts` (`DEFAULT_TEACHER_PASSWORD`, `DEFAULT_STUDENT_PASSWORD`).

## Data-model Gotchas (must know)

- **Programs/trainings — two sources**: DB tables `programs`/`trainings` drive all form dropdowns + `resolveProgramTrainingIds()` (student inserts); empty tables silently drop program/training. Static `PROGRAMS`/`TRAININGS`/`COURSES` in `src/lib/trainings.ts` only power student portal seeded schedule. `students` store only `program_id`/`training_id` FKs; `teachers` use free-text `program`/`training`/`specialty`.
- **Class assignment uses specialty aliases**: `teacherCourseAssignment()` resolves profile first, then `teachers.specialty` via hand-maintained `SPECIALTY_CLASS_ALIASES` in `api.ts` (aliases normalized by `normalizeSpecialtyKey()` where `&`→space), then teacher's courses. Targets are `"CODE / Name"` (avoid ambiguous bare names across programs). No FK; mismatches show amber banner on Class page. `supabase/backfill-teacher-classes.sql` is optional, idempotent, but flags 2 ambiguous rows — don't run blindly.
- **Soft delete by default**: `is_deleted=true` + `deleted_at`; list queries filter `.or("is_deleted.is.false,is_deleted.is.null")`. Trashed people cannot log in and their session ends (`getStudentById`/`getTeacherById` returns null). Payments have their own trash; students/teachers/publications/attendance share `GeneralTrashPage` (purge calls `hardDelete*`). App-level cascade only on exams (`deleteExamCascade` → grades); deleting a course hard-deletes it and the DB FK cascades its `course_reviews`.
- **Denormalized names**: `attendance`, `course_reviews` (snapshot `student_name`), `events` (`organizers`/`members`/`attendees` as `uuid[]`, no stored names) — resolve at read time and skip missing ids.
- **Courses**: `listTeacherCourses({ teacherId?, programId?, trainingId? })` — pass `{ teacherId }` for teacher-scoped contexts; `{}` only when fetching all. Add Course has **no** program/training selectors (inferred via `teacherCourseAssignment()`, refetched at save). `saveTeacherCourse()` throws on failure; `deleteTeacherCourse()` returns boolean. Thumbnails downscaled to ≤400px JPEG → `cours-covers` (DB stores absolute `thumbnail_url`). `published` = auto `published_at` (displayed as "Added <date>"). `day`/`time_slot` exist but not written.
  - `courses.materials` may be a **JSON string** on older rows (PostgREST/jsonb quirk) — always use `toMaterialList()`; also `toSkillList()` for `skills`. Wrap student detail sections in `ErrorBoundary`.
  - `courses.level/format/duration` are display strings, `skills` is `text[]` (not jsonb) — do not "normalize" without migrating.
  - Thumbnails: Storage wins → `thumbnailForTraining()` in `src/lib/courseDisplay.ts` looks up `src/assets/img/courses/<slug>.jpg` (accents/apostrophes → `-`) → gray placeholder.
- **Student courses merge**: static `COURSES` (seeded schedule, no id/teacherId) + live `courses` for student's class via `listTeacherCourses({ programId, trainingId })`, else client-side name fallback. Many trainings have no seeded courses.
- **Events vs Publications**: different tables. `events` = rich items created on the admin Events page; `events.type` is plain `text` with **no DB CHECK**, so the app's `EVENT_TYPES` union (Hackathon, Event, Publication, New Training, Certification) is the only limit. `partners` is jsonb `{name,link}`; older plain `text[]` read via `toPartnerArray()`. `attendees` (teacher RSVPs, added by an idempotent `ALTER`) is excluded from `saveEvent()` so the operator edit form cannot overwrite it; `setEventAttendance()` is a read-modify-write on the uuid[]. Covers → `event-covers`. The `publications` table is broadcast notifications only (`recipients` `text[]`; `type` constrained to `urgent|warning|info` in `src/pages/publications/publicationTypes.ts`).
- **Attendance (denormalized log)**: `absence/AttendanceLog.tsx` stores `id, type('student'|'teacher'), full_name, class_name, date, time, created_at` + optional `program/training` snapshots; **no** `student_id/teacher_id/present`. `attendanceToWriteRows()` always resolves program/training (explicit wins; backfill by lowercase name; `class_name` falls back to training→program→specialty→`"General"`). One table, no Save button, client-side filter. Students via `loadStudentAttendance()`.
- **Exams/Grades**: exam scoped to `teacher_id`; new exams store `type` + `duration` + `semester` (`'Semester 1' | 'Semester 2'`, plain text, no CHECK — `SEMESTER_OPTIONS` in `ExamsPage.tsx` is the only limit; probe before write, live tables need `supabase/exams-semester-migration.sql`); `program`/`training` are legacy snapshots for old rows only; the old `course` column is unused — live tables need `supabase/exams-type-duration-migration.sql`. Attachments: `file_name` holds the display name, `attachment_url` the public URL in the `exam` bucket (probe before write; live tables need `supabase/exam-attachment-migration.sql`). `ExamsNotesPage` is a tabs wrapper around `ExamsPage` + `GradesPage`. Delete cascades grades after confirm (`countGradesForExam` + `deleteExamCascade`). `saveGradesForExam` replaces all grades for exam (blank = clear). Roster via `classRosterForTeacher()`.
- **QCM**: `quizzes` (`teacher_id`, nullable `course_id`, `questions` jsonb `{id,text,options[4],correctIndex}[]` — **index**, not letter). Read via `toQuizQuestions()` (handles jsonb possibly returned as string). `quiz_responses` has unique `(quiz_id,student_id)`, stores answers as `{questionId:index}`, `score`. Published quizzes lock editing (unpublish to edit). Review panel resolves names via `classRosterForTeacher()` (unlisted → "Removed student"). Student side: `listPublishedQuizzes(courseIds)`, `listStudentQuizResponses()`, `submitQuizResponse()` (upsert on `(quiz_id,student_id)`), `scoreQuizAnswers()` (one response per quiz); quizzes with an empty `course_id` are visible to every student. Every QCM call runs `assertQuizzesReady()` first, so a partial live schema fails with the migration message instead of a raw PostgREST error.
- **Announcement unread badge**: `useUnreadAnnouncements(role)` counts `publications` whose `recipients` include the role minus ids in `src/lib/announcementReads.ts` (localStorage `ssm-read-announcements-<role>` — no per-user backend). `role` is the plural `RecipientType` (`"teachers" | "students"`), not `"teacher"`/`"student"`; only the teacher/student sidebars show the badge. The announcements pages mark the list read on mount; a custom event updates the sidebar badge immediately.
- **Payments audit**: `updatePayment()` diffs fields and **appends** one entry to `edit_history` jsonb (`changedAt, changedBy, changes:[{field,from,to}]`); `changed_by` is cookie role (`"operator"`). Soft-delete/restore only flip flags. Receipt: `pay/PaymentReceiptModal.tsx` prints only `#receipt-print-area` via `receipt-printing` body class + print CSS (hide chrome with `.receipt-no-print`).
- **Settings**: key/value `settings` table via `getSettings`/`saveSettings` (SQL null clears). Keys: `system_name`, `university_name`, `logo_url`, `language`, `dark_mode`, `license_activated_at`, `license_token`. Fallback to `ssm-settings` localStorage if table missing; writes mirror to cache. `dark_mode` toggles `.dark` class (applied at bootstrap in `main.tsx`). Language stored-only. System tab "Sync Data" runs `reconcileAttendanceProfiles()` (backfills NULL/generic program/training by case-insensitive name match, never overwrites stored values) — mirrors SQL `public.reconcile_attendance_profiles()`.
- **License**: no backend. Expiry = `license_activated_at` + fixed `LICENSE_TERM_MONTHS` (in `src/lib/license.ts`). Accepted tokens in `LICENSE_TOKENS` array; root `token.md` is a human mirror — **keep them in sync** (app cannot read markdown at runtime). All placeholders `fake-token-…`.
- **Dashboard**: `pages/dashboard/DashboardPage.tsx` via `getDashboardStats()` — active counts, 30-day attendance-rate proxy (capped 100%), paid/pending KPIs, last-6-month series (recharts).
- **Planning**: `teacher-portal/PlanningPage.tsx` filters by `teacherId`, hand-rolled Mon–Sun week (no date lib; anchor `startOfWeek(today)`, step ±7). Excel (SheetJS)/PDF (jspdf-autotable) export only viewed week, disabled if empty.
- **Bulk import**: `.xlsx/.csv` client-side via SheetJS (`pages/students/importStudents.ts`, `pages/teachers/importTeachers.ts`, `pages/absence/importAttendance.ts`), bulk-inserts via api.ts.

## Stack Quirks

- **Tailwind v4** via `@tailwindcss/vite` — **no** `tailwind.config.js`. Theme tokens in `@theme inline` in `src/index.css`.
- **shadcn/ui (Base UI)**: `"style": "base-nova"` in `components.json`, wraps `@base-ui/react` (not Radix). Add with `npx shadcn add <component>`; icons lucide-react.
- **Path alias**: `@/*` → `src/*` must stay in sync across `vite.config.ts`, `tsconfig.app.json`, `tsconfig.json`.
- **TypeScript**: `verbatimModuleSyntax` (type-only imports need `import type`), `erasableSyntaxOnly` (no enums/namespaces/parameter properties), `noUnusedLocals`/`noUnusedParameters`. `strict` not enabled. `dist/` gitignored.
