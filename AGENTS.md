# AGENTS.md

Frontend-only React 19 + Vite 8 + TypeScript SPA ("SSM") backed by Supabase. No tests, no CI.

## Commands

- Dev: `npm run dev` (or `RUN.bat`, which just calls it). No port is pinned in `vite.config.ts`.
- Lint: `npm run lint` (oxlint — there is no ESLint; config `.oxlintrc.json`). Two warnings are pre-existing baseline in `src/components/ui/button.tsx` and `tabs.tsx` (`react/only-export-components`); don't chase them.
- Typecheck: `npx tsc -b`. `npm run build` = `tsc -b && vite build`. There is no typecheck/test script — do not invent test commands.
- Verify a change with `npm run lint`, then `npx tsc -b`.
- `.\check.ps1` probes live Supabase (connectivity, table existence, anon read, row counts) — run it when pages fail. It hard-fails unless `.env.local` defines `VITE_SUPABASE_PUBLISHABLE_KEY` (it does NOT accept `VITE_SUPABASE_ANON_KEY`, even though the app does), and it only checks students/teachers/payments/attendance/courses/exams/grades/publications/planning. `cleardata.ps1` wipes localStorage, but session state lives in cookies — it does not log you out; treat it as stale.
- Before changing code that queries Supabase, confirm the live table columns (schema.sql can drift from the deployment). The custom OpenCode command `verify-fix` (`.opencode/command/verify-fix.md`) does this; ask the user rather than guessing.

## Backend & environment

- Supabase is REQUIRED: `.env.local` in the project root with `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` **or** `VITE_SUPABASE_PUBLISHABLE_KEY`. `src/lib/supabase.ts` throws at import time when either is missing, so every page fails; restart Vite after editing env files. Gotcha: root `.env.example` documents only `ANON_KEY`, while `supabase/.env.example` and `check.ps1` use `PUBLISHABLE_KEY` — copy the publishable-key variant if you want `check.ps1` to run. Env files are gitignored via `*.local`.
- `supabase/schema.sql` is the executable source of truth (idempotent; paste into the Supabase SQL Editor — it is never auto-applied). Tables: `programs`, `trainings`, `students`, `teachers`, `payments`, `attendance`, `courses`, `exams`, `grades`, `publications`, `planning`, `settings`. RLS grants full anon access; there are NO Supabase Auth accounts — "auth" is the cookie scheme below.
- ALL Supabase I/O goes through `src/lib/api.ts` (2400 lines). Rows are snake_case; mappers convert to/from the camelCase shapes the UI uses. Add tables/columns/mutations there, never inline in components. Helpers `withTimeout`, `hasColumn`, `resolveProgramTrainingIds`, `detectPaymentsCapabilities` are module-private.
- Capability probing pattern: optional columns are detected ONCE at runtime and never referenced when absent (PostgREST rejects unknown columns). `detectPaymentsCapabilities()` for `payments.is_deleted/deleted_at/edit_history`; `generalTrashCapabilities()` for `is_deleted/deleted_at` on students/teachers/publications/attendance; `hasCourseMaterialsColumn()` for `courses.materials`. When a column is missing the app degrades to an in-memory map and the UI shows a "not available" notice — do not "fix" this by hardcoding the column.
- Realtime: live-updating pages call `subscribeToTable(table, () => refetch())` from api.ts. Subscribers: `StudentsPage`→students, `TeachersPage`→teachers, `UserManagementPage`→students+teachers, student `CoursesPage`/`StudentDashboardPage`→courses, `MyCoursesPage`→courses, `MyClassPage`→students+courses. A table must be in the `supabase_realtime` publication to deliver events — the block at the bottom of `supabase/schema.sql` currently lists **only** students, teachers, courses, publications (not attendance or payments). Those same pages also call `useRefetchOnFocus(refetch)` (`src/hooks/useRefetchOnFocus.ts`): a fallback that refetches once when the tab/window regains focus after ≥5s hidden, not the primary sync.
- Session state is in **cookies** via `src/lib/session.ts` (`role`, `currentStudentId`, `currentTeacherId`). localStorage is used only for the `ssm-settings` fallback cache. Route guards in `src/App.tsx` read `role`; `loadCurrentStudent()`/`loadCurrentTeacher()` read the ID and fetch the record — a null result ends the session via each layout's deleted-record effect.

## Architecture

- Four routes only (`src/App.tsx`): `/login`, `/dashboard` (operator), `/student`, `/teacher`; guards are role-aware, `/login` and the wildcard bounce by role. `/dashboard` mounts `src/pages/DashboardPage.tsx`, a thin wrapper that only renders `<Layout />` — the real stats page is `src/pages/dashboard/DashboardPage.tsx`.
- Sections are NOT routes; they swap via `useState` + a `pages` map inside each layout: `src/components/Layout.tsx` (Dashboard, Students, Teachers, Pay — a nested submenu of Payments|History|Trash via `children` — Absence, Publications, User Management, Trash, Settings), `teacher-portal/TeacherLayout.tsx` (Courses, Exams & Notes, Class, Planning), `student-portal/StudentLayout.tsx` (Dashboard, Courses, My Payment, Announcements, Absence, Settings; Dashboard is the default landing). To add a section, edit that layout's `menuItems` AND `pages`. `MyInfoPage.tsx` exists in student-portal but is wired into no menu. Note two different Settings pages: operator `settings/SettingsPage.tsx` vs student `student-portal/StudentSettingsPage.tsx`.
- Login is ONE page for all roles (`src/pages/LoginPage.tsx`), single name+password form, checked in order: (1) `admin`/`admin123` → operator; (2) teachers by **exact case-sensitive** trimmed full-name match; (3) students by **case-insensitive** trimmed match. `blocked === true` on a matched account shows "Access has been blocked by the center."; a wrong password always shows the generic "Incorrect name or password." (the blocked check runs only after credentials match).
- Pages are async over Supabase; loading/error UI comes from `src/components/DataState.tsx` (`DataLoading`/`DataError`). Feature folders live in `src/pages/<feature>/` as `<Feature>Page.tsx` plus list/form subcomponents.
- Accounts are just `password`/`blocked` columns on the people tables (null password = no account). `src/pages/users/userAccounts.ts` holds `DEFAULT_TEACHER_PASSWORD = "tch123"`, `DEFAULT_STUDENT_PASSWORD = "std123"`, `defaultAccountPassword(kind)`, `hasAccount()`; Add/Edit forms, Create Account and Reset Password all default to the kind's value.

### Data-model traps

- **Programs/trainings have TWO sources.** The DB `programs`/`trainings` tables drive every form dropdown (Student/Teacher forms, Add Absence) via `listPrograms()`/`listTrainings()`, and student inserts resolve the displayed strings back to FK ids inside `resolveProgramTrainingIds()` — so an EMPTY `programs`/`trainings` table silently drops program/training on new students. Separately, the static `PROGRAMS`/`TRAININGS`/`COURSES` strings in `src/lib/trainings.ts` only power the student portal's seeded schedule. `students` stores ONLY `program_id`/`training_id` FKs; `teachers` carry free-text `program`/`training`/`specialty`.
- **Portals share storage; no copies.** `payments` keeps only `id, student_id, amount, plan_type, payment_date, status, created_at, is_deleted, deleted_at, edit_history` — names are joined from `students` at read time, so renaming/removing columns breaks inserts. Teacher exams/grades/class are scoped by `teacher_id` ownership plus `classRosterForTeacher()` (joins `courses` by `teacher_id`, then matches students by program/training). Changing an entity's shape breaks both sides.
- **Soft delete everywhere.** Deletes set `is_deleted = true` + `deleted_at`; every list query filters with `.or("is_deleted.is.false,is_deleted.is.null")`. Trashed people cannot log in (login searches `listTeachers`/`listStudents`) and their session ends because `getStudentById`/`getTeacherById` return null. Payments keep their own trash (`pay/PaymentTrashPage.tsx`); students/teachers/publications/attendance share `trash/GeneralTrashPage.tsx` (attendance rows reuse the person's type, details show `program - training`).
- **Payments audit trail.** Every edit goes through `updatePayment()`, which diffs changed fields and APPENDS one `{changedAt, changedBy, changes:[{field,from,to}]}` entry to the payment's `edit_history` jsonb; the History page reads it via `listPaymentHistory()`. `changed_by` is the cookie role, always `"operator"` (Pay is operator-only). Soft-delete/restore only flip flags. The Payments list's printer icon opens `pay/PaymentReceiptModal.tsx` — an 80mm receipt that prints only `#receipt-print-area` via the `receipt-printing` body class + `@media print` rules in `src/index.css` (use `.receipt-no-print` to hide chrome).
- **Courses** (`trainings.ts` + `teacher-portal/MyCoursesPage.tsx`, My Courses|Add Course tabs): `listTeacherCourses({ teacherId?, programId?, trainingId? })` filters server-side; pass `{ teacherId }` for the My Courses tab, Exams dropdown, Planning options, `classRosterForTeacher` and the `teacherCourseAssignment` fallback so a teacher never sees another teacher's rows; `{}` only where ALL courses are needed. The Add Course form has NO program/training selectors — they come from `teacherCourseAssignment()` (profile first, else the class of the teacher's existing courses, else legacy text), re-fetched at save time, so a course can never be written outside the teacher's own assignment. `saveTeacherCourse()` THROWS on failure (callers catch and show inline); `deleteTeacherCourse()` returns a boolean. Thumbnails are downscaled client-side to a ≤400px JPEG and uploaded to the **`cours` Supabase Storage bucket** (`uploadCourseThumbnail`); the DB stores only `thumbnail_url`. `uploadCourseMaterial()` uploads real material files to that same bucket and returns a public URL. Bucket + anon read/insert policies come from the idempotent Storage block in `schema.sql`; missing bucket → readable "bucket does not exist" error. `published` is an auto `published_at` timestamp (never asked, preserved on edit) shown as "Added <date>". `courses.day`/`time_slot` still exist but the form no longer writes them. Delete confirms via AlertDialog, no cascade. Cards render through the shared `components/CourseCardsGrid.tsx`: course Storage thumbnail wins, else a static `src/assets/img/courses/<slug>.jpg` (training slug, accents/apostrophes → `-`), else a gray placeholder.
- **Student courses are a merge** (`trainings.ts` `loadScheduledCourses`): the static seeded `COURSES` schedule (no `id`/`teacherId`) plus live `courses` rows for the student's class via `listTeacherCourses({ programId, trainingId })`, falling back to a client-side `courseInClass` name match when the student has no FKs. Most current `TRAININGS` entries have no seeded `COURSES` key, so those classes legitimately show only teacher-added courses.
- **Attendance** is one denormalised log (`absence/AttendanceLog.tsx`): `id, type ('student'|'teacher'), full_name, class_name, date, time, created_at` + optional `program`/`training` snapshots and soft-delete columns — no `student_id`/`teacher_id`/`present`, no joined names. `insertAttendanceRecords`/`updateAttendanceRecord` ALWAYS resolve program/training (`attendanceToWriteRows`): explicit form/file values win, gaps are backfilled from the person's record by lowercase full-name lookup; `class_name` falls back to training → program → specialty → `"General"` (NOT NULL in live deployments). The Absence page is ONE table, no tabs, no Save button; `loadAttendanceRecords()` fetches all rows and the search box filters client-side. Students read their own history via `loadStudentAttendance()`.
- **Exams/grades**: exams are scoped at creation to the exam's `teacher_id` with `program`/`training` snapshotted from the chosen course; the file input stores only the file NAME. Deleting an exam cascades grades after a count confirm (`countGradesForExam` + `deleteExamCascade`). `saveGradesForExam` replaces all of one exam's grades (blank input = grade cleared); roster is `classRosterForTeacher`.
- **Settings** (`settings/SettingsPage.tsx`, General|Preferences|System|About) uses the `settings` key/value table via `getSettings`/`saveSettings` (SQL null = cleared). Keys: `system_name`, `university_name`, `logo_url`, `language`, `dark_mode`. Reads fall back to the localStorage cache `ssm-settings` when the table is missing; `saveSettings` mirrors to the cache first, then best-effort upserts. `dark_mode` toggles the app-wide `.dark` class via `applyDarkMode()`, applied at bootstrap in `main.tsx` (cached value first, then async DB refresh) so it works before login. `system_name` drives branding via `getSystemName()` (falls back to "SSM"); `language` is stored-only — no UI is translated. The System tab's "Sync Data" runs `reconcileAttendanceProfiles()`, which backfills NULL/generic `program`/`training` on attendance rows by case-insensitive name match and never overwrites stored values; the same logic exists as SQL function `public.reconcile_attendance_profiles()` in `schema.sql`.
- **Dashboard** (`pages/dashboard/DashboardPage.tsx`): `getDashboardStats()` aggregates active counts, a 30-day attendance-rate proxy (presence records ÷ 30 days × active people, capped at 100%), paid/pending KPIs and last-6-month by-plan/by-program series via recharts.
- **Planning** (`teacher-portal/PlanningPage.tsx`): `planning` rows filtered strictly by `teacherId`; hand-rolled Mon–Sun week view with NO date library (a `Date` anchored on `startOfWeek(today)`, stepped ±7). Excel (SheetJS) / PDF (jspdf-autotable) export only the viewed week and are disabled when empty.
- **Bulk import** parses `.xlsx`/`.csv` client-side with SheetJS (`pages/students/importStudents.ts`, `pages/teachers/importTeachers.ts`, `pages/absence/importAttendance.ts`) then bulk-inserts through api.ts.

## Non-code folders

`init/` and root `*.md` (`PRD*.md`, `TDD*.md`, `backend.md`, `vibe-code-prompts-*.md`), plus `claude/` and `md/`, are product specs / reference material, not app code. `README.md` is stock Vite boilerplate. `accessloginpage.md` documents portal logins: only `admin`/`admin123` works out of the box; teacher/student logins exist only after an operator creates the record (passwords default to `tch123`/`std123`). `superbase/` (extra "e") is a stray folder holding a DB password — never read it or use it.

## Stack quirks

- Tailwind v4 via `@tailwindcss/vite`: intentionally NO `tailwind.config.js`. Theme tokens/colors live in the `@theme inline` block of `src/index.css`; edit CSS there.
- shadcn/ui is the **Base UI** flavor (`"style": "base-nova"` in `components.json`): `src/components/ui/*` wrap `@base-ui/react`, not Radix. Add primitives with `npx shadcn add <component>`; icons are lucide-react.
- Path alias `@/*` → `src/*` must stay in sync across `vite.config.ts`, `tsconfig.app.json` and root `tsconfig.json`.
- TS style: `verbatimModuleSyntax` (type-only imports need `import type`), `erasableSyntaxOnly` (no enums, namespaces, or parameter properties), `noUnusedLocals`/`noUnusedParameters`. Note `strict` is NOT enabled in `tsconfig.app.json` — don't assume strict null checks.
