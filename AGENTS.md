# AGENTS.md

Frontend-only React 19 + Vite 8 + TypeScript SPA ("SSM") backed by Supabase. No tests, no CI, no ESLint.

## Commands

- Dev: `npm run dev` (or `RUN.bat`, which just calls it). No port is pinned in `vite.config.ts`; `cleardata.ps1` assumes `http://localhost:5173`.
- Lint: `npm run lint` (oxlint, config `.oxlintrc.json`). Verified baseline is **2 warnings, 0 errors** — `react/only-export-components` in `src/components/ui/button.tsx` and `tabs.tsx`. Don't chase them.
- Typecheck: `npx tsc -b`. `npm run build` = `tsc -b && vite build`. There is no typecheck or test script — do not invent test commands.
- Verify a change in that order: `npm run lint`, then `npx tsc -b`.
- `.\check.ps1` probes live Supabase (connectivity, table existence, anon read, row counts) — run it when pages fail. It hard-fails unless `.env.local` defines `VITE_SUPABASE_PUBLISHABLE_KEY` (it does NOT accept `VITE_SUPABASE_ANON_KEY`, even though the app does), and it checks only students/teachers/payments/attendance/courses/exams/grades/publications/planning — **not** `events`, `course_reviews`, `settings` or the Storage buckets.
- `cleardata.ps1` only runs `localStorage.clear()` in the browser over CDP; session state is in cookies, so it does not log you out.
- Before changing code that queries Supabase, confirm live table columns (`supabase/schema.sql` drifts from the deployment). The OpenCode command `verify-fix` (`.opencode/command/verify-fix.md`) does this — use it or ask the user, don't guess.

## Backend & environment

- Supabase is REQUIRED: `.env.local` at the project root with `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` **or** `VITE_SUPABASE_PUBLISHABLE_KEY` (this repo currently uses the publishable variant). `src/lib/supabase.ts` throws at import time when either is missing, so every page fails; restart Vite after editing env files. Root `.env.example` documents only `ANON_KEY` — the publishable key form is what `check.ps1` and `supabase/.env.example` expect. Env files are gitignored via `*.local`.
- `supabase/schema.sql` is the executable source of truth (idempotent; paste into the Supabase SQL Editor — it is never auto-applied, so any new table/bucket/column is inert until the user runs it). Tables: `programs`, `trainings`, `students`, `teachers`, `payments`, `attendance`, `courses`, `course_reviews`, `events`, `exams`, `grades`, `publications`, `planning`, `settings`. RLS grants full anon access; there are NO Supabase Auth accounts — "auth" is the cookie scheme below.
- ALL Supabase I/O goes through `src/lib/api.ts` (~3100 lines). Rows are snake_case; mappers convert to/from the camelCase shapes the UI uses. Add tables/columns/mutations there, never inline in components. Module-private helpers: `withTimeout`, `hasColumn`, `resolveProgramTrainingIds`, `detectPaymentsCapabilities`, `generalTrashCapabilities`, `hasEventsTable`, `hasCourseMaterialsColumn`.
- **Capability-probing pattern**: optional schema is detected ONCE at runtime and never referenced when absent (PostgREST rejects unknown columns). When something is missing the app degrades to an in-memory map and the UI shows a "not available" notice — do not "fix" this by hardcoding the column. Live: `detectPaymentsCapabilities()` (`payments.is_deleted/deleted_at/edit_history`), `generalTrashCapabilities()` (`is_deleted/deleted_at` on students/teachers/publications/attendance), `hasCourseMaterialsColumn()` (`courses.materials`), `hasEventsTable()`. The older course-detail-metadata probes were RETIRED — `subtitle/level/duration/format/skills/syllabus` and `course_reviews` are now written unconditionally.
- **Storage buckets are split per media type** (`src/lib/courseBuckets.ts` is the single source of truth for the upload *and* display paths): `cours-covers` (thumbnails + non-video/non-PDF), `cours-PDF`, `cours-videos`, plus `event-covers` and `university-logo`. `cours` is a legacy bucket still holding the absolute `thumbnail_url` of older course rows — kept, no migration. Bucket ids are case-sensitive (`cours-PDF`). Buckets + anon read/insert policies come from the Storage block in `schema.sql`; a missing bucket surfaces as a readable "does not exist" error.
- Realtime: live pages call `subscribeToTable(table, () => refetch())`. Subscribers: `StudentsPage`→students, `TeachersPage`→teachers, `UserManagementPage`→students+teachers, `MyClassPage`→students+courses, student `CoursesPage`/`StudentDashboardPage` and `MyCoursesPage`→courses, `CourseReviewsSection`→course_reviews, `EventHistoryPage`→events. A table only delivers events if it is in the `supabase_realtime` publication — the block at the bottom of `schema.sql` lists **students, teachers, courses, publications, course_reviews, events** (not attendance or payments). The same pages also call `useRefetchOnFocus(refetch)` (`src/hooks/useRefetchOnFocus.ts`): one refetch when the tab regains focus after ≥5s hidden, not the primary sync.
- Session state is in **cookies** via `src/lib/session.ts` (`role`, `currentStudentId`, `currentTeacherId`). localStorage is only the `ssm-settings` fallback cache. Guards in `src/App.tsx` read `role`; `loadCurrentStudent()`/`loadCurrentTeacher()` fetch the record and a null result ends the session via each layout's deleted-record effect.

## Architecture

- Four routes only (`src/App.tsx`): `/login`, `/dashboard` (operator), `/student`, `/teacher`; role-aware guards, `/login` and the wildcard bounce by role. `/dashboard` mounts `src/pages/DashboardPage.tsx`, a thin wrapper that only renders `<Layout />` — the real stats page is `src/pages/dashboard/DashboardPage.tsx`.
- Sections are NOT routes; they swap via `useState` + a `pages` map inside each layout. To add a section, edit BOTH the menu list and the `pages` record:
  - operator: menu list lives in `src/components/sectionMenu.ts` (shared, typed `MenuKey`), `pages` map + rendering in `src/components/Layout.tsx`. Sections: Dashboard, Students, Teachers, Pay (submenu Payments|History|Trash), Absence, Publications, Events (submenu New Event|Event History), User Management, Trash, Settings. Pay and Events are collapsible parents that list their own key as the first child so the parent highlights.
  - `teacher-portal/TeacherLayout.tsx` (own `menuItems` + `pages`): Courses, Exams & Notes, Class, Planning.
  - `student-portal/StudentLayout.tsx` (own `menuItems` + `pages`): Dashboard, Courses, My Payment, Announcements, Absence, Settings; Dashboard is the default landing. `MyInfoPage.tsx` exists but is wired into no menu.
  - Two different Settings pages: operator `settings/SettingsPage.tsx` vs student `student-portal/StudentSettingsPage.tsx`.
- Login is ONE page for all roles (`src/pages/LoginPage.tsx`), single name+password form, checked in order: (1) `admin`/`admin123` → operator; (2) teachers by **exact case-sensitive** trimmed full-name match; (3) students by **case-insensitive** trimmed match. `blocked === true` on a matched account shows "Access has been blocked by the center."; a wrong password always shows the generic "Incorrect name or password." (the blocked check runs only after credentials match).
- Pages are async over Supabase; loading/error UI comes from `src/components/DataState.tsx` (`DataLoading`/`DataError`). Feature folders live in `src/pages/<feature>/` as `<Feature>Page.tsx` plus list/form subcomponents.
- Branding: `main.tsx` fetches settings once at bootstrap and publishes them via `src/lib/branding.ts` (`useBranding()`, `brandTitle()`, `setBrandingFromSettings()`); layouts and `LoginPage` read that cache rather than re-fetching. `system_name` falls back to "SSM" (`getSystemName()`).
- Accounts are just `password`/`blocked` columns on the people tables (null password = no account). `src/pages/users/userAccounts.ts` holds `DEFAULT_TEACHER_PASSWORD = "tch123"`, `DEFAULT_STUDENT_PASSWORD = "std123"`, `defaultAccountPassword(kind)`, `hasAccount()`; Add/Edit forms, Create Account and Reset Password all default to the kind's value.

### Data-model traps

- **Programs/trainings have TWO sources.** The DB `programs`/`trainings` tables drive every form dropdown (Student/Teacher forms, Add Absence) via `listPrograms()`/`listTrainings()`, and student inserts resolve the displayed strings back to FK ids inside `resolveProgramTrainingIds()` — so an EMPTY `programs`/`trainings` table silently drops program/training on new students. Separately, the static `PROGRAMS`/`TRAININGS`/`COURSES` strings in `src/lib/trainings.ts` only power the student portal's seeded schedule. `students` stores ONLY `program_id`/`training_id` FKs; `teachers` carry free-text `program`/`training`/`specialty`.
- **Portals share storage; no copies.** `payments` keeps only `id, student_id, amount, plan_type, payment_date, status, created_at, is_deleted, deleted_at, edit_history` — names are joined from `students` at read time, so renaming/removing columns breaks inserts. Teacher exams/grades/class are scoped by `teacher_id` ownership plus `classRosterForTeacher()` (joins `courses` by `teacher_id`, then matches students by program/training). Changing an entity's shape breaks both sides. The teacher's Class page ALSO has a manual class import: two `programs`/`trainings` dropdowns + Import, backed by `studentsForClass({ programId?, trainingId?, program?, training? })`, which deliberately reads through `listStudents()` so the soft-delete filter still applies.
- **Soft delete everywhere.** Deletes set `is_deleted = true` + `deleted_at`; every list query filters `.or("is_deleted.is.false,is_deleted.is.null")`. Trashed people cannot log in (login searches `listTeachers`/`listStudents`) and their session ends because `getStudentById`/`getTeacherById` return null. Payments keep their own trash (`pay/PaymentTrashPage.tsx`); students/teachers/publications/attendance share `trash/GeneralTrashPage.tsx`. **Anything holding ids of soft-deletable people must not cascade or hard-delete.**
- **Denormalised names, never FKs to people.** `attendance`, `course_reviews` (`student_name` snapshot) and `events` (`organizers`/`members` as `uuid[]` with no FK and no stored name) resolve people at read time and simply skip ids that no longer resolve.
- **Courses.** `listTeacherCourses({ teacherId?, programId?, trainingId? })` filters server-side; pass `{ teacherId }` for My Courses, the Exams dropdown, Planning options, `classRosterForTeacher` and the `teacherCourseAssignment` fallback so a teacher never sees another teacher's rows; `{}` only where ALL courses are needed. The Add Course form has NO program/training selectors — they come from `teacherCourseAssignment()` (profile first, else the class of the teacher's existing courses, else legacy text), re-fetched at save time. `saveTeacherCourse()` THROWS on failure (callers catch and show inline); `deleteTeacherCourse()` returns a boolean; delete confirms via AlertDialog, no cascade. Thumbnails are downscaled client-side to a ≤400px JPEG and uploaded to `cours-covers`; the DB stores only the absolute `thumbnail_url`. `published` is an auto `published_at` timestamp (never asked, preserved on edit) shown as "Added <date>". `courses.day`/`time_slot` still exist but the form no longer writes them.
  - `courses.materials` is jsonb that older rows stored as a **JSON string** — calling `.map()` on it throws "materials.map is not a function". Always go through `toMaterialList()` (and `toSkillList()` for `skills`); `CourseCardsGrid`/`CourseDetail`/`StudentCourseDetail` guard for this and the student detail wraps sections in `ErrorBoundary`.
  - `courses.level`, `format`, `duration` hold short DISPLAY STRINGS (`'Beginner'`, `'Video & Document'`, `'1h 30m'`), not enum keys or minute counts, and `skills` is `text[]` not jsonb — do not "normalize" them without migrating rows.
  - Cards render through `components/CourseCardsGrid.tsx`: course Storage thumbnail wins, else a static `src/assets/img/courses/<slug>.jpg` (training slug, accents/apostrophes → `-`), else a gray placeholder.
- **Student courses are a merge** (`trainings.ts` `loadScheduledCourses`): the static seeded `COURSES` schedule (no `id`/`teacherId`) plus live `courses` rows for the student's class via `listTeacherCourses({ programId, trainingId })`, falling back to a client-side `courseInClass` name match when the student has no FKs. Most current `TRAININGS` entries have no seeded `COURSES` key, so those classes legitimately show only teacher-added courses.
- **Events** (`pages/events/`) are NOT `publications` (that table is a broadcast message to recipients). `events.type` is free text, app-constrained to `EVENT_TYPES` (Hackathon, Event, Publication, New Training, Certification) so a new kind needs no migration. `partners` is jsonb `{name, link}`; rows written by an older build stored a plain `text[]` and are read as name-only partners via `toPartnerArray()`. Covers upload to `event-covers`. Saving hands the operator to Event History; editing is driven from Event History back into the New Event form via `initialEvent`.
- **Attendance** is one denormalised log (`absence/AttendanceLog.tsx`): `id, type ('student'|'teacher'), full_name, class_name, date, time, created_at` + optional `program`/`training` snapshots — no `student_id`/`teacher_id`/`present`, no joined names. `insertAttendanceRecords`/`updateAttendanceRecord` ALWAYS resolve program/training (`attendanceToWriteRows`): explicit form/file values win, gaps are backfilled from the person's record by lowercase full-name lookup; `class_name` falls back to training → program → specialty → `"General"` (NOT NULL in live deployments). The Absence page is ONE table, no tabs, no Save button; `loadAttendanceRecords()` fetches all rows and the search box filters client-side. Students read their own history via `loadStudentAttendance()`.
- **Exams/grades**: exams are scoped at creation to the exam's `teacher_id` with `program`/`training` snapshotted from the chosen course; the file input stores only the file NAME. Deleting an exam cascades grades after a count confirm (`countGradesForExam` + `deleteExamCascade`). `saveGradesForExam` replaces all of one exam's grades (blank input = grade cleared); roster is `classRosterForTeacher`.
- **Payments audit trail.** Every edit goes through `updatePayment()`, which diffs changed fields and APPENDS one `{changedAt, changedBy, changes:[{field,from,to}]}` entry to the payment's `edit_history` jsonb; the History page reads it via `listPaymentHistory()`. `changed_by` is the cookie role, always `"operator"` (Pay is operator-only). Soft-delete/restore only flip flags. The Payments list's printer icon opens `pay/PaymentReceiptModal.tsx` — an 80mm receipt that prints only `#receipt-print-area` via the `receipt-printing` body class + `@media print` rules in `src/index.css` (use `.receipt-no-print` to hide chrome).
- **Settings** (`settings/SettingsPage.tsx`, General|Preferences|System|About|License) uses the `settings` key/value table via `getSettings`/`saveSettings` (SQL null = cleared). Keys: `system_name`, `university_name`, `logo_url`, `language`, `dark_mode`, `license_activated_at`, `license_token`. Reads fall back to the localStorage cache `ssm-settings` when the table is missing; `saveSettings` mirrors to the cache first, then best-effort upserts. `dark_mode` toggles the app-wide `.dark` class via `applyDarkMode()`, applied at bootstrap in `main.tsx` (cached value first, then async DB refresh) so it works before login. `language` is stored-only — no UI is translated. The System tab's "Sync Data" runs `reconcileAttendanceProfiles()`, which backfills NULL/generic `program`/`training` on attendance rows by case-insensitive name match and never overwrites stored values; the same logic exists as SQL function `public.reconcile_attendance_profiles()` in `schema.sql`.
- **License** (`src/lib/license.ts` + `settings/LicenseTab.tsx`, `LicenseRenewDialog.tsx`): there is NO licensing backend. Expiry is derived from the `license_activated_at` setting plus a fixed `LICENSE_TERM_MONTHS`; renewing re-stamps the activation date. The accepted token pool is the `LICENSE_TOKENS` array in `license.ts`, and root `token.md` is its human-readable mirror — the app can't read a root markdown file at runtime, so **keep the two in sync**. All current entries are `fake-token-…` placeholders.
- **Dashboard** (`pages/dashboard/DashboardPage.tsx`): `getDashboardStats()` aggregates active counts, a 30-day attendance-rate proxy (presence records ÷ 30 days × active people, capped at 100%), paid/pending KPIs and last-6-month by-plan/by-program series via recharts.
- **Planning** (`teacher-portal/PlanningPage.tsx`): `planning` rows filtered strictly by `teacherId`; hand-rolled Mon–Sun week view with NO date library (a `Date` anchored on `startOfWeek(today)`, stepped ±7). Excel (SheetJS) / PDF (jspdf-autotable) export only the viewed week and are disabled when empty.
- **Bulk import** parses `.xlsx`/`.csv` client-side with SheetJS (`pages/students/importStudents.ts`, `pages/teachers/importTeachers.ts`, `pages/absence/importAttendance.ts`) then bulk-inserts through api.ts.

## Stack quirks

- Tailwind v4 via `@tailwindcss/vite`: intentionally NO `tailwind.config.js`. Theme tokens/colors live in the `@theme inline` block of `src/index.css`; edit CSS there.
- shadcn/ui is the **Base UI** flavor (`"style": "base-nova"` in `components.json`): `src/components/ui/*` wrap `@base-ui/react`, not Radix. Add primitives with `npx shadcn add <component>`; icons are lucide-react.
- Path alias `@/*` → `src/*` must stay in sync across `vite.config.ts`, `tsconfig.app.json` and root `tsconfig.json`.
- TS style: `verbatimModuleSyntax` (type-only imports need `import type`), `erasableSyntaxOnly` (no enums, namespaces, or parameter properties), `noUnusedLocals`/`noUnusedParameters`. `strict` is NOT enabled — don't assume strict null checks. `dist/` exists locally but is gitignored build output; ignore it.

## Non-code folders & secrets

- `init/`, root `*.md` (`PRD*.md`, `TDD*.md`, `backend.md`, `project-info.md`, `vibe-code-prompts-*.md`), plus `claude/` and `md/`, are product specs / reference material, not app code. `README.md` is stock Vite boilerplate. `accessloginpage.md` documents portal logins: only `admin`/`admin123` works out of the box; teacher/student logins exist only after an operator creates the record (passwords default to `tch123`/`std123`).
- `superbase/` (extra "e") is a stray folder holding a DB password (`passwordBD`) — never read it or use it. Never commit credentials or `.env.local`.
