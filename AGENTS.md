# AGENTS.md

Frontend-only React 19 + Vite 8 + TypeScript SPA ("SSM") over Supabase. No tests, no CI. Lint is **oxlint**, not ESLint, and there is no formatter config.

## Commands

- **Dev**: `npm run dev` (or `RUN.bat`). No port is pinned in `vite.config.ts`; `cleardata.ps1` assumes `http://localhost:5173`.
- **Verify before claiming done**: `npm run lint`, then `npx tsc -b`. `tsc -b` is the only typecheck (oxlint is not type-aware); don't add ESLint, Prettier or a `typecheck` script. Four warnings are pre-existing (`only-export-components` in `src/components/ui/button.tsx`/`tabs.tsx`, `set-state-in-effect` in `StudentProfilePage.tsx`/`TeacherProfilePage.tsx`) — don't add new ones or rewrite unrelated pages to silence them.
- **Build**: `npm run build` (`tsc -b && vite build`); `npm run preview` serves `dist/`.
- **Live DB probe**: `.\check.ps1` (connectivity, tables, anon read, QCM columns, then a throwaway `quizzes` insert/delete). It needs root `.env.local` with `VITE_SUPABASE_URL` + `VITE_SUPABASE_PUBLISHABLE_KEY` and ignores `VITE_SUPABASE_ANON_KEY`; `.env.example` ships only the anon name, so add the publishable key yourself. `.\probe-qcm.ps1` is the QCM-only variant.
- **Clear local state**: `.\cleardata.ps1` clears only `localStorage` over CDP (`localhost:5173`, debug port 9222). Sessions live in cookies, so it does not log you out.
- **Schema first**: live columns drift from `schema.sql` — confirm them before editing Supabase-querying code via `/verify-fix` (`.opencode/command/verify-fix.md`) or by asking the user. Never guess a column.

## Environment & Backend

- `.env.local` at the **root only** (`supabase/…` env files are never loaded) needs `VITE_SUPABASE_URL` plus `VITE_SUPABASE_ANON_KEY` or `VITE_SUPABASE_PUBLISHABLE_KEY`. `src/lib/supabase.ts` throws at import when missing; restart Vite after env edits.
- **No Supabase Auth, no per-user RLS**: every client shares the anon/publishable key and `schema.sql` creates `<table>_anon_all` policies (`using (true) with check (true)`), so RLS grants no authorization — never store anything sensitive. Passwords are plaintext columns compared client-side; `@supabase/ssr` is installed but unused for auth.
- **`schema.sql` is not auto-applied**: paste `supabase/schema.sql` into the SQL Editor. `CREATE TABLE IF NOT EXISTS` never adds columns to existing tables, so column gaps need the patches in `supabase/*.sql` (qcm, publications-type, exams-type-duration, exam-attachment, exams-semester, exams-class, planning-*, user-profiles, profile-picture-bucket, absences, absence-billets, events-location, branches-materials, center-settings, teacher-avatar, payments-plan…). Writes must fail with an actionable "run `<file>.sql`" message.
- **Single data layer**: all Supabase I/O lives in `src/lib/api.ts` (~5.8k lines). Add tables/columns/mutations there, never inline in components. DB rows are `snake_case`; mappers convert to `camelCase`. Wrap every query builder in `withTimeout()` (15s default, 8s probes) or a page hangs on Loading forever; throw `new Error(error.message)` and render via `errorMessage()`. No react-query/SWR: pages fetch in `useEffect` into local state and refresh via realtime or `useRefetchOnFocus()`.
- **Optional schema is probed at runtime**: never reference a column that may not exist — PostgREST rejects unknown columns and kills the whole query. Probes live at the top of `api.ts` (`hasBranchesSchema`, `detectPaymentsCapabilities`, `hasCourseMaterialsColumn`, `hasEventsTable`, `hasEventAttendeesColumn`, `hasExamAttachmentColumn`, `hasExamSemesterColumn`, `examClassColumns`, `hasPlanningClassTimeColumns`, `missingQuizColumns`/`assertQuizzesReady`). Only `hasUserProfilesTable`, `generalTrashCapabilities` and the `paymentsSupports*` checks are exported, so components must use the guarded `list*`/`save*` functions rather than probe themselves. Reads degrade to empty/in-memory data; writes throw the migration hint.
- **Storage buckets are case-sensitive**: `cours-covers`, `cours-PDF`, `cours-videos` (paths in `src/lib/courseBuckets.ts`), `event-covers`, `university-logo`, `Logo`, `exam`, `profilePictuer` (hardcoded in `api.ts`). The legacy `cours` bucket still serves older absolute `thumbnail_url`s.
- **Realtime** publication covers `students, teachers, courses, publications, course_reviews, events, quizzes, quiz_responses` (plus `center_settings` once `supabase/center-settings-realtime-migration.sql` runs) — not attendance or payments. Use `subscribeToTable(table, () => refetch())`.
- **Session**: cookies via `src/lib/session.ts` (`role`, `currentStudentId`, `currentTeacherId`, 24h `max-age`) — users re-login daily by design. `localStorage` holds the `ssm-settings` cache, the `ssm-theme`/`ssm-language` mirrors, `ssm-read-announcements-<role>`, dashboard widget prefs (`ssm-dashboard-widgets`, `:teacher:<id>`, `:student:<id>`), the teacher social-link mirror (`ssm-teacher-social:<id>`), `ssm-backup-history` and `ssm-billet-prints`. Avatars are Storage URLs in `user_profiles`, not local state.

## Architecture

- **Routes (4)**: `/login`, `/dashboard` (operator), `/student`, `/teacher`, role-guarded in `src/App.tsx` with a wildcard bounce. Two `DashboardPage.tsx` files exist: `src/pages/DashboardPage.tsx` is the thin `/dashboard` wrapper around `<Layout />`; `src/pages/dashboard/DashboardPage.tsx` is the operator stats section.
- **Sections are state, not routes**: each layout swaps sections through a `pages` map driven by `src/hooks/viewHistory.ts` + `ViewHistoryProvider.tsx`. `active` is `currentSection.key`; sidebar clicks call `pushSection(key, label)` (never local `setState`), and `HeaderBackButton` pops. Adding a section means updating **both** the menu and the `pages` record or it never renders. Nested full pages register with `useNestedView(open, key, label, onClose)`.
- **Operator** (`src/components/sectionMenu.ts` + `Layout.tsx`): Pay/Absence/Events are collapsible parents. `planification` lists every training by track as one card (deduplicated by `(program_id, name)` and folded name, never fanned out per teacher) and opens the same `BranchPlanningPage` slot grid the Branches page uses. `branches` is the class file: `BranchesPage` → `BranchDetailPage` (monochrome zinc class view) with `branch_materials` (one teacher per material, matched strictly against `teachers.specialty` via `materialSpecialty.ts`), the roster from `students.training_id`, and "Open timetable" → `BranchPlanningPage`. Teacher/room/class clashes are reported by `planningConflicts.ts`, never blocked.
- **Teacher** (`TeacherLayout.tsx`): `pages` is built **inside** the component (closes over `setOpenEventId`). Its collapsible parent `"Exams"` has a key outside the `PageKey` union. Settings = `TeacherSettings.tsx` (`Profile`/`General`): name via `updateTeacherProfile` **and** `upsertUserProfile`, avatar → `profilePictuer` + `user_profiles.avatar_url`, social links in the same row with a localStorage mirror, plus shared dark-mode/language.
- **Student** (`StudentLayout.tsx`): its collapsible `"Exams"` holds `exams-list` and `exam-scores`; `planning`, `events`, `qcm` sit beside it. Exams/planning are read-only. `listPlanningForClass(classNameFor(program, training), { programId, trainingId })` fetches all planning rows and filters in `api.ts`: a matching `program_id`+`training_id` pair wins, a conflicting id excludes the row, otherwise the `class_name` label is compared with `normalizeCourseName()` (containment allowed, so `"Training"` still matches `"CODE · Training"`) — a byte-exact SQL `eq` used to hide entries. `listExamsForStudent(program, training)` matches the `exams.program`+`training` text snapshot. The student page groups by the stored `YYYY-MM-DD` string (no `new Date`), has `All | Courses | Exams | PFE` zinc pills, and its dates go through the locale-aware `scheduleDates` helpers. `scheduleDates.ts` holds Monday-based week helpers (string `YYYY-MM-DD` compares, no UTC shift). `MyInfoPage.tsx` exists but is not in the menu; student settings are `StudentSettings.tsx`, not the operator Settings page.
- **People profile pages** (`StudentProfilePage.tsx`, `TeacherProfilePage.tsx`): a row click swaps the section content for a full-page profile, registered by the holder (`StudentsPage`, `MyClassPage`, `TeachersPage`) with `useNestedView("student-profile" | "teacher-profile")`. Both mount the shared `ProfileParts.tsx` — style changes go there, never in one page alone. Data: avatar/name from `user_profiles` (`UserAvatar` falls back to initials), attendance by denormalized name, teacher data from `classRosterForTeacher` + `listPlanning` + teachers-only publications via `Promise.allSettled`. `onEdit` is operator-only. Editing is a right-side sheet (`EditTeacherSheet.tsx` / `EditStudentSheet.tsx`): the photo block uploads immediately (not on "Save changes") so tables/profile update live; `TeacherForm` only creates.
- **Login** (`LoginPage.tsx`): `admin`/`admin123` → operator; teachers match the **exact, case-sensitive** trimmed full name, students case-insensitively. `blocked` is checked only after the password matches; failures share one generic message.
- **Branding/i18n**: `src/main.tsx` loads settings once via `src/lib/branding.ts` (`useBranding`, `system_name` fallback "SSM"), applies `dark_mode`, and syncs `language`. `src/lib/i18n.ts` is a module-level `useSyncExternalStore` store (not context). The dictionary is keyed by the **English copy itself** (`FRENCH["Students"]`), so `t("Students")` works and untranslated keys fall back to English; translation is manual. `LANGUAGE_OPTIONS` (`src/lib/languages.ts`) is `en`/`fr` only, stale `"ar"` normalizes to `en`. Operator Settings applies language on **Save**, teacher/student Settings instantly.
- **Accounts**: `password`/`blocked` on people tables (null password = no account). Defaults `tch123`/`std123` in `src/pages/users/userAccounts.ts`.

## Data-model Gotchas

- **Programs/trainings have two sources**: DB `programs`/`trainings` drive dropdowns and `resolveProgramTrainingIds()` (empty tables silently drop the value on insert); static `PROGRAMS`/`TRAININGS`/`COURSES` in `src/lib/trainings.ts` only seed the student schedule. `students` store FKs; `teachers` use free-text `program`/`training`/`specialty`.
- **Class assignment uses specialty aliases**: `teacherCourseAssignment()` tries the profile, then `teachers.specialty` through hand-maintained `SPECIALTY_CLASS_ALIASES` (keys are `normalizeSpecialtyKey()` output, `&`→space), then the teacher's courses. Targets are `"CODE / Name"`; there is no FK, mismatches show an amber banner. `supabase/backfill-teacher-classes.sql` is optional and flags ambiguous rows — don't run it blindly.
- **Soft delete by default**: `is_deleted=true` + `deleted_at`; lists filter `.or("is_deleted.is.false,is_deleted.is.null")`. Trashed people cannot log in (`getStudentById`/`getTeacherById` return null). Payments have their own trash; students/teachers/publications/attendance share `GeneralTrashPage` (`hardDelete*`). App-level cascade only for exams (`deleteExamCascade` → grades); deleting a course hard-deletes it and the FK cascades `course_reviews`.
- **Denormalized names**: `attendance` and `course_reviews` snapshot `student_name`; `events` stores `organizers`/`members`/`attendees` as `uuid[]` with no names — resolve at read time and skip missing ids.
- **`user_profiles` owns avatars and social links** (`user_id`, `role`, `first_name`, `last_name`, `avatar_url`, `linkedin_url`, `whatsapp_number`, `github_url`). `user_id` is the `teachers`/`students` row id and `role` is `'teacher'`/`'student'`. Uniqueness is **(`user_id`, `role`)** under `unique_user_role`, so `upsertUserProfile()` must pass `{ onConflict: "user_id,role" }` — PostgREST otherwise defaults to the `id` PK and inserts duplicates or fails 42P10. Read/write only through `getUserProfile`/`listUserProfiles`/`upsertUserProfile`/`hasUserProfilesTable`; `src/lib/userProfile.ts` caches and notifies so headers update instantly. `teachers.avatar_url` is an optional best-effort mirror (probed; migration `teacher-avatar`). Fresh DBs need `user-profiles-migration.sql`.
- **Courses**: `listTeacherCourses({ teacherId?, programId?, trainingId? })` — pass `{ teacherId }` in teacher contexts, `{}` only for everything. Add Course has no program/training selectors (inferred via `teacherCourseAssignment()`). `saveTeacherCourse()` throws; `deleteTeacherCourse()` returns a boolean. Thumbnails downscale to ≤400px JPEG → `cours-covers`. `courses.materials` can be a JSON **string** on old rows — always `toMaterialList()`/`toSkillList()`; `skills` is `text[]` and level/format/duration are display strings, so don't "normalize" without a migration. Student courses merge static `COURSES` with live rows: `loadScheduledCourses()` fetches the whole `courses` table and filters client-side by FK pair or `normalizeCourseName()` text (case/accent/punctuation-insensitive) — a server-side `program_id`/`training_id` filter silently dropped legacy rows with NULL FKs. The student page's support filter is built from the displayed courses, defaults to `all` (`All supports`), and its empty state offers a localized reset. Thumbnail fallback chain: Storage → `thumbnailForTraining()` → gray placeholder.
- **Events vs Publications (different tables)**: `events` are rich items; `type` is plain `text` (only `EVENT_TYPES` limits it), `partners` is jsonb `{name,link}` (old `text[]` via `toPartnerArray()`), `location` is optional/probed, `gifts_awards` is a comma-separated multi-select (`splitGifts()`/`formatGift()`). The creator is the full-page `EventsView.tsx`; `AddEventModal.tsx` is an unimported near-twin — edit it alongside or delete it. `attendees` (teacher RSVPs) is excluded from `saveEvent()`; `setEventAttendance()` is a read-modify-write. Covers → `event-covers`. `publications` is broadcast-only (`recipients` `text[]`, `type` limited to `urgent|warning|info`).
- **Attendance is a denormalized log** (`src/pages/absence/AttendanceLog.tsx`): writes `type('student'|'teacher'|'full_class')`, `full_name`, `class_name`, `date`, `time`, optional `program`/`training`, and (after `absences-migration.sql`) `target_type, user_id, program_tier, training_id, absence_date, absence_time, time_from, time_to`. Reads probe those columns; writes always include all of them. `time`/`time_from`/`time_to` are `time`-typed — put a single clock value there and the `"08:00 - 10:00"` window in text `absence_time`; reads rebuild the window. `attendanceToWriteRows()` resolves program/training and falls back `class_name` → training → program → specialty → `"General"`. One table, no Save button, client-side filtering; students read via `loadStudentAttendance()`.
- **Absence billets**: every student row gets a Ticket action. `AbsenceBilletModal.tsx` **archives on mount** (StrictMode-safe ref, retry on failure) via `saveAbsenceBillet()` and prints only `#billet-print-area` with runtime `@page { size: A5 portrait }`. `resolveBilletContext()` reads `planning` for that class/date and returns subject + teacher **only when unambiguous** (otherwise subject falls back to training → program and the teacher stays blank). `absence_billets` is a snapshot (`attendance_id` with no FK, `absence_date` NOT NULL, `billet_code` NOT NULL/UNIQUE carrying the same `BIL-YYYYMMDD-XXXXXX` as `verification_code`), so editing/purging the log never changes a handed-out ticket. `AbsenceBilletsView.tsx` lists newest first; Preview reopens the modal without re-archiving. Print counts are a localStorage hint only (`ssm-billet-prints`).
- **Exams/Grades**: exams are scoped to `teacher_id`; new rows store `type`, `duration`, `semester` (`'Semester 1'|'Semester 2'`, plain text, probe before writing). The base schema has **no `exams.program_id`** — `program` (programs.code) and `training` (trainings.name) are text snapshots. `CreateExamView` fills them from the class picked in the form (`teacherExamClasses()`: `branch_materials` + `planning`, narrowed to the teacher's ERP/SAP material, first assigned class as default); when `exams-class-migration.sql` ran it also writes `branch_id`/`program_id`/`training_id`/`subject` (probed, skipped otherwise). `listExamsForStudentClass()` treats a snapshot naming another of the teacher's branches as authoritative, so a CAP exam never leaks into BTP/BTS, while blank/legacy snapshots keep the transverse-teacher fallback. Blank legacy rows stay invisible to students until `exams-class-backfill.sql`. Attachments keep `file_name` + public `exam` bucket URL. The Exams parent swaps `CreateExamView`, `ExamsTableView` and `ExamScoreView` (not tabs), sharing `useTeacherExams()` + `ExamForm.tsx`. Delete confirms via `countGradesForExam` then `deleteExamCascade`; `saveGradesForExam` replaces every grade (blank clears). Rosters come from `classRosterForTeacher()` (an exam's own class roster wins when it is one of the teacher's branches); `grades` has no FK to exams, so student scores join client-side via `listExamsByIds`.
- **QCM**: `quizzes` (`teacher_id`, nullable `course_id`, `questions` jsonb `{id,text,options[4],correctIndex}[]` — **numeric index**, not letter) read via `toQuizQuestions()` (jsonb may be a string). `quiz_responses` is unique on `(quiz_id,student_id)` and stores `{questionId:index}` + `score`. Published quizzes lock editing. An empty `course_id` means visible to every student. Every call runs `assertQuizzesReady()` first.
- **Payments audit**: every action appends one `edit_history` jsonb entry (`changedAt, changedBy, actionType, changes, details?`) with `changed_by` from the cookie role. `insertPayment(s)` seeds `created`; `updatePayment` appends `updated` with `{field,from,to}` diffs; soft delete/restore append `deleted`/`updated` and touch only the payment flags. Legacy entries without `actionType` read as `updated`. Receipts print only `#receipt-print-area` via the `receipt-printing` body class.
- **Settings**: single-row `public.center_settings` (`id = 1`, CHECK-pinned) via `getSettings`/`saveSettings` — one upsert of every column on **Save**, `updated_at` stamped, logo uploaded to `Logo` → `logo_url`, downloads stamp `last_backup_at`. Columns include `system_name`, `university_name`, `language`, `dark_mode`, `academic_year`, `timezone`, `currency`, `session_timeout_minutes`, license fields, `last_backup_at`. Boot reads row 1 before first render; reads fall back to legacy key/value `settings` rows and the `ssm-settings` cache, writes throw a "run `center-settings-migration.sql`" message. "Sync Data" runs `reconcileAttendanceProfiles()` (backfills NULL/generic program/training, never overwrites).
- **License**: no backend. Keys are `PREFIX-XXXX-XXXX-XXXX-XXXX[-XXXX]` (4 or 5 groups; `M-` 30 days, `3-` 90, `Y-` 365; `src/lib/license.ts`, mirror in `token.md`). Activation stores key/plan/status/expiry on `center_settings` id 1. `LicenseGate` in `App.tsx` swaps the whole tree for `LicenseLockScreen.tsx` when expiry is missing or past.
- **Backup & Export** (`src/pages/settings/BackupExportPage.tsx`, sidebar only): one **Full System Backup** section (JSON for restore, or one SQL script) over `FULL_BACKUP_TABLES` in `backupFormat.ts` — 14 core tables incl. `center_settings`; missing optional tables (e.g. `operators`, `payment_history`) are reported as skipped. The trash switch feeds SQL/JSON; Excel always strips trash. Restore wizard (`RestoreDataModal.tsx`) inspects → merge/upsert or replace → per-table progress, downloads a safety JSON backup first, and writes via `upsertBackupRows()`/`replaceBackupTable()`. History is localStorage (`ssm-backup-history`), not a table.
- **Planning**: `PlanningPage.tsx` filters by `teacherId` and hand-rolls Mon–Sun weeks (anchor `startOfWeek(today)`, step ±7). Rows store `course`, optional `class_name`/`session_time`, `room_name`, `session_type`, `topic` (app calls it `content`), operator-only `notes`, and a `jury_teacher_ids uuid[]` PFE panel. A `category` (`course|exam|pfe`) is derived from `session_type` via `planningCategoryFor()` — never a second column — so the operator tabs, student schedule and branch grid keep working. The teacher dialog shows a Course & Materials / Exam Planning / PFE Planning switcher, narrows the session types per category, relabels the notes field, and (Course only) attaches a daily material in `material_url`/`material_name` (`planning-material-migration.sql`, uploaded through `uploadCourseMaterial`). The page filters by category and adds the category + material to the Excel/PDF export and the student schedule. `updatePlanning` writes `notes`/`jury_teacher_ids`/`material_*`/`date` only when passed, so inline edits don't wipe them or shift the day; an empty material means "clear". Shared form `src/components/PlanningEntryForm.tsx` (teacher page vs operator editor); its `requireContent`/`defaultSessionTime`/`onDraftChange` props and `lockClass`/`subjects`/`teacherQualifier`/`timeSlots`/`showNotes` options serve the branch grid, and `layout="grid"` is the wide landscape modal. 11 session types grouped by `PLANNING_TABS` in `planning.ts`: Timetable (`In-class`, `Online`), Exam Schedule (`DS`, `TP`, `TD`, `Principale`, `Exam`, `SYNTHESE`), PFE (`PFE`, `STAGE`, `Soutenance`); labels are English i18n keys. `examMode` opens `AddExamSessionModal.tsx`, `pfeMode` opens `AddPFESessionModal.tsx` (jury panel, `teacher_id` = first juror). Teacher Planning is editable; student Planning is read-only and class-scoped. Excel/PDF export covers only the viewed week.
- **Bulk import**: `.xlsx`/`.csv` parsed client-side with SheetJS (`importStudents.ts`, `importTeachers.ts`, `importAttendance.ts`) then bulk-inserted through `api.ts`.

## Stack Quirks

- **Tailwind v4** via `@tailwindcss/vite`: there is **no** `tailwind.config.js`; theme tokens live in `@theme inline` in `src/index.css`.
- **shadcn/ui on Base UI**: `"style": "base-nova"` wraps `@base-ui/react`, not Radix. Add with `npx shadcn add <component>`; icons are lucide-react. Base UI `Select.Value` prints the **raw value** unless the root gets `items={[{ value, label }]}`, so a sentinel like `__all` leaks into the trigger without one.
- **Toolbar toggles**: list/add switches use `SegmentedTabsList`/`SegmentedTabsTrigger` from `src/components/ui/segmented-tabs.tsx` (still Base UI Tabs). Profile and Settings strips keep `TabsList variant="line"`.
- **Icons**: FontAwesome 7 is used only for brand icons on the two profile pages. Import icons explicitly (`faLinkedin`, `faWhatsapp`, `faEnvelope`) — FA 7 removed `byPrefixAndName`. Size via font-size (`text-xl`), never `w-*`. `config.autoAddCss = false` is set in `main.tsx`, so new FA icons need no CSS.
- **Path alias**: `@/*` → `src/*` is duplicated in `vite.config.ts`, `tsconfig.app.json` and `tsconfig.json` — keep all three in sync.
- **TypeScript**: `verbatimModuleSyntax` (use `import type`), `erasableSyntaxOnly` (no enums/namespaces/parameter properties), `noUnusedLocals`/`noUnusedParameters`. `strict` is **not** enabled; don't turn it on casually.
